# 数据结构与编号规则

## 当前文件

- `01_literature/papers.csv`：每个独立研究作品一行，`当前馆藏状态` 标识当前在用文献，Paper ID 永久不随排序变化。P001–P003 已固定；新增论文取下一个未使用编号。空白元数据表示尚未在馆藏中确认。
- `01_literature/zotero_mapping.csv`：每条 Zotero 文献记录一行，连接 Paper ID、Item Key、Collection、附件 Key、重复证据、读取状态和当前/回收站状态。数据库中的历史 Collection 关系不得直接当作在用馆藏。已清理的历史 Item Key 仍保留作审计追踪，明确标为不可再访问；两组需保留批注或 PDF 版本的附件 Key 已转到当前主条目。
- `01_literature/sources.csv`：每个来源或版本一行，记录 DOI、官方 PDF 链接、馆藏状态和原文核验状态。`官方PDF链接`为空表示尚未确认；可读本地附件不等于研究内容已核验。
- `01_literature/cards/`：已核验的逐篇阅读卡片；`batches/` 保存阶段性总表和审计。

## 版本与证据

同 DOI、同标题、同作者及相同 PDF 正文可判为重复馆藏条目；字节不同但正文等价时保留差异说明。预印本与正式发表版在 `sources.csv` 分别成行，不混用其页码和实验数字。若不同版本的结论发生实质变化，先审查后决定是否建立新 Paper ID。

年份优先使用已核验的正式出版信息；馆藏日期与 PDF 日期冲突时在索引中标注待核验，不静默覆盖。作者、Venue、DOI 的来源可为 Zotero 元数据或已核验原文，缺失则留空。研究任务、机制和关联类型只在全文阅读后填写；标题推测不计为已分析。

## 后续结构

`02_synthesis/` 保存任务、方法、数据集和对比矩阵；`03_research_gaps/` 的每个 Gap 需独立编号、关联论文、支持与反面证据及状态；`04_cross_domain_transfer/` 记录源方法原任务、核心机制、假设、障碍和竞争研究；`05_research_ideas/` 的每个 Idea 需关联 Gap、源方法、创新性审查与实验设计；`06_experiments/` 只保存实验计划、配置、结果和结论；`07_manuscripts/` 保存大纲、图表与草稿。需要时再创建这些目录和文件。

禁止提交 PDF、数据库、全文缓存、数据集、权重、凭据、账号信息和绝对本地路径。
