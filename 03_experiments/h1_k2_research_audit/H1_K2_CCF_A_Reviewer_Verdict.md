# 严格审稿视角（研究者模拟，非真实评审意见）

审稿对象是当前证据所能形成的论文，不评价尚未实施方法的成绩。等级锚点：不足=缺核心证据；初步=探索性可查；可用=可复核；成熟=跨条件与强替代解释已闭合。等级不对应录用概率。

| 维度 | 当前 | 判断依据 |
|---|---|---|
| Novelty | 不足 | 关系风险/联合失败/表示恢复已有直接工作，尚无独立技术贡献 |
| Technical Soundness | 初步 | 指标正确，但跨条件任务不同，机制归因不成立 |
| Methodological Depth | 不足 | 尚无方法与中介干预，只有最终标签 |
| Experimental Rigor | 初步 | 固定样本与协议良好；标签人审、QB、官方协议、外部数据缺失 |
| Reproducibility | 可用（归档）/初步（模型复现） | 原始预测、哈希、代码与时序完整；依赖/权重索引修复需复核 |
| Generality | 不足 | 一模型一探索子集，不支持普遍规律 |
| Practical Relevance | 初步且明确 | 请求风险判别有应用价值，但当前数据不等于真实部署分布 |
| Feasibility | 冻结诊断可用，训练未知 | 单图约42s，NF4推理约8.14GiB；LoRA/干预未测 |

## 视角一：NLP / Multimodal Learning方法审稿人

**Strengths**：完整的成对记录使风险翻转和过度泛化可检查；区分任务与单模态标签，有机会形成精细的条件依赖研究；主模型可冻结，工程可复用。

**Weaknesses**：36对已被反复用于看结果、选现象和设计方法，不能再作最终独立测试；PairAcc在本数据预测结构下与Accuracy存在恒等关系，不能当两项独立发现；没有事实/指称标签，所有“binding failure”仍是猜测；与ThinkingGuard相同的实体—关系Motivation，不因更换模块名称而新颖。

**Questions**：为何不能用官方五步、关系Prompt、同预算CoT、简单线性头或已知双线性融合解决？是否证明无关因素不影响判别？新方法输入是否暗含配对另一侧/侧别/金标归因？同样监督和token预算下还有效吗？独立测试按情境还是按图像随机划分？

**Fatal flaws（若如此写则不可接受）**：把11个不同任务的标签差异宣称新融合机制；把模型解释当忠实内部推理；把事后A级子集包装为预注册test；只报告提高Recall却不报FPR。

**Missing evidence**：隐藏模型输出的人审、任务控制、感知/绑定分离、额外Prompt信息量对照、强方法baseline、第二公开数据和独立模型。现在直接投方法论文建议拒；诊断验证可以有条件继续。

**提升路径**：首先把动机缩到一个经证伪筛选仍成立的关系条件错误；再证明最小算法具有该关系的选择性控制与跨场景泛化。不能将“增加中间步骤”列成技术贡献。

## 视角二：AI Security / Multimodal Safety审稿人

**Strengths**：原始失败未被丢弃，INVALID与NOT_RUN处理透明；明确20GiB、免API与固定revision，有复现实践价值；请求风险与拒答分离符合guard评价需要。

**Weaknesses**：当前没有部署威胁模型、检测政策和授权缺证处理；涉及政治批评、转录、道具的GT不稳定；安全模型的训练/Test实际隔离未知；高拒答不是输入检测正确，模型在不同prompt下错误也不等于能被攻击者稳定利用。

**Questions**：系统保护谁、拦截什么、攻击者控制图/文哪些部分、是否知道检测器？正常用户中Review/误报成本怎样估计？若方法依赖固定关系识别器，攻击者改指称/嵌字/布局后是否失效？能否移除guard不是本输入筛查系统应承诺解决的白盒部署边界。

**Fatal flaws**：把MMAligner拒答率拿来与Joint Accuracy排名；把未知授权默认为犯罪；把安全词包含率当无害性；没有Safe负例或只在TG失败样本上测试；在训练集阈值调优后宣称独立安全保证；只给固定非适应性攻击而宣称全面稳健。

**Missing evidence**：可信输入风险真值、同FPR/同coverage比较、自然正常请求、独立外部数据、适应性语义扰动；若论文主张防御，须明确攻击预算与查询上限。没有明确攻击目标时，优先以检测可靠性论文定义，不硬套越狱防御。

**提升路径**：提供可审计的风险政策、证据依赖和失败边界；同FPR下提高风险召回，同时证明收益来自正确使用图像证据。若声称内部机制，应有等norm随机/反向/非目标干预；若仅外部分类器，则不必承诺修复生成模型所有安全性。

## Motivation的三种强度

**当前最强且成立**：在固定量化快照与统一短标签协议下，ThinkingGuard对部分图文请求的预测与TriggerBench标签不一致；其中任务定义和样本可判定性必须先厘清，才能研究检测是否依赖正确证据。

**更有吸引力但待证**：即使关键视觉事实正确、规范充分，检测器仍会把请求绑定到错误目标；针对这一条件依赖的干预能降低漏检而不扩大误报。必须等人审、Prompt控制与绑定干预通过才能写成Motivation。

**不可写**：首次发现图文融合削弱安全；已证明风险信息在隐藏层丢失；ThinkingGuard不会看图；已用36对证明普遍安全缺陷；MMAligner没有做检测所以不存在竞争；低于某F1即足以支持CCF-A方法创新。

## 贡献账本

科学发现：当前只有可追溯的行为模式，内部机制未成立。方法：没有已验证新算法。实验：可复核探索协议与独立复算，不能拆成三个方法贡献。资源：小型审核/诊断工具可作辅助贡献，不能单独替代方法论文。

总建议：**PIVOT；机制诊断CONDITIONAL GO；当前方法稿NO-GO**。科研上值得用低成本门槛回答一次，但不值得在前提未闭合时开展LoRA、全量扩测和多模块开发。若KT1/2否定现象，停止是正确产出。
