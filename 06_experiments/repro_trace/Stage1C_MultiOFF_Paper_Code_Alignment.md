# TRACE-S1C · MultiOFF 论文与代码对应

- MultiOFF 2020 Table 2 的文本 CNN 为 F1 0.54、P 0.39、R 0.84。TRACE Table 6 的 “MultiOFF Baseline” 引用这三个数字。原数据论文另有 VGG16、GloVe 和图文 early fusion 等条件。该行的 F1 与本轮宏 F1 的定义须分别核对。 [MultiOFF 论文](https://aclanthology.org/2020.trac-1.6.pdf) · [TRACE Table 6](https://arxiv.org/html/2504.17902v2#S4.T6)
- TRACE Table 6 另列 ViT-L/14 projection FT（作者报告 Acc 0.604、F1 0.377）与完整 TRACE（作者报告 Acc 0.678、F1 0.673）。后者用 CLIP-XLM-R-ViT-H/14、末四层、分类及 relevance。前者最接近本轮预定路线，代码可追溯但存在协议差异，不把数字直接当作已复现实验。
- 固定提交的 `MultiOFF/multioff_proj_ft.py` L36–176、214–257、294–360、395–461 使用 HF ViT-L/14、原始 `sentence`、冻结整个 CLIP，以图文 pooler 分别映射并归一化，再逐元素相乘，经三层 MLP 分类。还有图像及文本辅助头，三项 focal 权重为 1/0.3/0.7。默认 seed 42，物理批 512，AdamW（LR 1e-4、衰减 1e-4），Dev Macro-F1 选 epoch，评估阈值 0.5。脚本另外在 Dev 上搜索 WiSE-FT alpha，测试时使用已选模型。 [固定 projection 源码](https://github.com/surrey-nlp/TRACE/blob/83ecb799f897fe275185e082ee9a669f7d04bfaa/MultiOFF/multioff_proj_ft.py)
- `adapted_author_baseline` 使用同一提交的原始分类器、collate 与 focal 类，以及预先验证的 HF revision。整 epoch 的梯度按样本权重累积来保留作者逻辑批大小，使用 BF16 和确定性 CUDA，单卡，seed 42，epoch 内采样由 seed + epoch 生成。去除已不可用的 scheduler `verbose` 参数。预先固定最高 20 epoch、Dev Macro-F1 选最佳 epoch、patience 5、概率阈值 0.5。此配置省略 WiSE-FT alpha 搜索，Test 仅评价最终已选 Dev checkpoint 一次。单卡累积与物理批、BF16 与先前精度、采样次序及 WiSE-FT 差异均可能影响数值。
- `clip_roberta_multioff.py` L30–36、46–108、535–545、561–624 的活动模型是 OpenCLIP `roberta-ViT-B-32` / `laion2b_s12b_b32k`，与 HF ViT-L/14 的权重、文本编码器和分词格式均不同。它需要增强 Caption CSV，代码还使用 1/0.3/0.7 的分类/对比/relevance。评价在每个被评估批的标签上重搜阈值，包括 Test。这条脚本路径无法证明论文 Table 6 的 XLM-R ViT-H/14 配置或提供无泄漏分数。 [固定 OpenCLIP 源码](https://github.com/surrey-nlp/TRACE/blob/83ecb799f897fe275185e082ee9a669f7d04bfaa/MultiOFF/clip_roberta_multioff.py)
- 固定 TRACE 文件树提供生成脚本，未找到作者原始 InternVL/Gemini 两列或带 split/ID 的完整合并文件。公开 Releases 页无发布项。作者原论文提供联系渠道。如需原件，应请求 FHM/MultiOFF 原始两列、对齐键、所用模型版本与实验 checkpoint。 [固定源码目录](https://github.com/surrey-nlp/TRACE/tree/83ecb799f897fe275185e082ee9a669f7d04bfaa) · [作者发布页](https://github.com/surrey-nlp/TRACE/releases) · [TRACE 论文](https://ojs.aaai.org/index.php/AAAI/article/view/41220)

作者发布的 3 个 CSV 各有 1 条找不到同名原图。预先启用完整样本分析，在原 split 内过滤缺图，正式本地分母为 444/148/148。作者原脚本遇到缺图会递归改取下一条，本轮保留可追溯的固定样本集合。此数据差异也可能影响结果。 [实际数据审核](Stage1C_MultiOFF_Data_Audit.md)
