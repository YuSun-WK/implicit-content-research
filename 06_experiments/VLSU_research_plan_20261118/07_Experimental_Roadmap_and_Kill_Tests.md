# 实验路线与 Kill Tests

目标是联合安全 S/B/U 分类，以及有独立证据的跨模态决策与迁移。计划沿用论文各任务的规范和授权。所有运行时间和显存都是预算估算。当前已完成静态证据核验和小样本下载解码，以下模型实验待执行。

## Stage 0｜数据与文献门

### 0a. 固定 VLSU 并建立合法可用样本清单

1. 固定 CSV blob、代码、各主机请求日期、解码器和预处理版本。对授权范围内图片批量检查并限速，GET、去重和 PIL 解码。记录变更 URL、字节/pixel hash、状态、大小、类型、原因。破图、非图、来源改变和无法取用样本明确缺失。每组报告原分母、成功分母、失败原因、域/时间影响；不以样本缺失默认算模型错误或代理填补。随机抽查图片与原任务是否仍对应，保留合法来源记录。完整计数和小样本现状见[审计](01_Current_Research_Audit.md)。
2. 在全可用数据构建连通组。先并合同图源 ID、归一 URL、字节/像素哈希、同 prompt，辅以 pHash/嵌入高近邻、标题风格、OCR、常见生成模板、视觉来源/同一事件。如果常用泛文本形成巨组，主协议整组冻结；另给全局泛提示移除的敏感性结果。阈值以人工小样本盲看和训练元数据确定，报告近似阈值而非称已排除所有重复。对每域列信息是否可用、精确重叠、近似重叠与排除率。
3. 两个协议在立项时选主次。**VLSU-External** 将所有可用样本作外部测试，阈值、温度、提示、模型与方法在其他验证集冻结；不参加训练或阈值选择。若三类头需要额外合法 S/B/U 来源，先确认来源。**VLSU-GroupSplit** 用 70/15/15 近似比例作同组监督训练。它是新协议，不能与原论文官方整库零样本 F1 直接对比。按联合标签、常见模式和类别在连通组层做贪心分层或整数优化；只用训练集设权重。独立再做类别／来源留一的可行泛化协议。若使用 GroupSplit，报告相同测试子集上的绝对指标和任何外部验证集。
4. 所有方案都保留联合标注完整的 not_sure 样本，图像等级辅助损失掩码，两单侧等级均真时才进标准模式和 Both-Correct 指标。19 个标准模式中，17 个是论文对齐名单，另外两个单例附录计数；6 个问号模式也单列。稀有组不强制每折出现，采用独立组折叠并记录覆盖。若在探索阶段已有人工筛选，不使用同组作为最终测试。未调整采样的 15% 留出预计每个 35 例子组约 5 例，不能作为独立成功门。
5. 把许可证和模型预训练不可知区分。CSV CC BY-NC-ND，第三方图源授权逐类核查；使用内部绘图和统计数据共享许可避免分发改编。训练 backbone 记数据截止和已知重叠。冻结权重能减少同对照之间的混淆，但无法排除预训练见过公共素材。独立测试时保留重叠审计，单报已知和可疑近重复的敏感性结果。 [CC 许可](https://creativecommons.org/licenses/by-nc-nd/4.0/legalcode.en)

### 0b. 唯一优先 Kill Test｜闭环支持审计（CPU）

**低成本输入。** 先取合法可访问的标签/元数据。Hateful Memes 有 benign confounders 并可做二分类原型，作者控制访问；实际原图/文本必须确认同身份与许可。MemeCF 论文提供关键模态变化，当前链接仓库仍只有待发布的说明。解释不能用于推断第四角真值。FBHM 论文与代码可读，当前仓库可见树以方法文件为主，未取得逐例标签包，需使用作者许可的释放。HoliSafe 有 train/test 和相同图对，HF 受控，原图与政策须核实。MSSBench 有同文变图，可作备选 B，但修订文献发现标签、图像和请求关系有问题，应先用独立复核清单。TriggerBench Train/Test 在 H1 清单中由 2,800 同文配对构成，精确路径二部图的两个分割均为森林，优先供单边配对的备选。H1 的 36 对经历探索，不进入最终留出。 [HM 条款](https://www.drivendata.org/competitions/70/hateful-memesphase/) · [MemePIVOT 论文](https://aclanthology.org/2026.findings-emnlp.1329/) · [FBHM 官方仓库](https://github.com/hate-alert/fbhm) · [HoliSafe 数据](https://huggingface.co/datasets/etri-vilab/holisafe-bench) · [MSSBench](https://github.com/UCSB-AI/MSSBench) · [MSSBench 审计](https://arxiv.org/html/2611.01125)

**执行。** 按共同策略→来源→端点→单侧等级建图，完全重复同图文边先合并。用 UTF-8 正文 NFKC+casefold+空格作为诊断键，涉及语义时回到原文和渲染像素。计算 m,n,c、环秩、非零标签对比数、四格/长环、不同类别及背景的覆盖。检查 Hateful Memes 若把同 OCR 文本固化在像素中的情况，只有独立的底图身份确认才可作主对照。选择完全不相交的题材或模板训练与测试组，并联系数据来源口径。对于真正已有的可信人审场景直接用作者标注。仅当少数必要端点缺标时，允许一次 ≤2 人日、最多 24 个四格的可行性盲核，用原 rubric 同政策独立判四格、记录不确定及一致性，不启动新大规模收集。小检查可以测标签有效性，通常不足以单独提供三类完整实证。对于缺边，项目的二元推断可做备选 B 或支持不足报告，不补虚构金标。

**建议门槛预注册。** 二类机制小试起点为至少 40 个非重叠、非零对比训练簇、20 个开发簇、30 个独立评估簇，覆盖至少两个来源或题材组。闭环总数之外另报独立来源/模板数，彼此共享节点的大量循环不当独立样本。三类立项要在同一规范中有含 B 的可信对比，且需至少两个独立来源或模板族、每个需要主张的方向足够独立组。首轮可用 20–30 组做明确的开发探索，正式主张在事前按配对差预期与可检测效应估算样本量。预算内全部数据有环秩零、只有预测标签、或非零对比能被来源/OCR 鉴别器轻易解释时为 NO-GO。少量三类组仅形成证据不足的判断；二类可继续作为机制代理，不能支持三类主贡献。三类配对仍无来源时，完整 A–D 三类迁移中 D 需要标记阻断原因，保留 A–C 和另立的二类机制试验。

以已核验的 [Cycle OE](https://arxiv.org/html/2610.23248) 为强制对照，继续补查稀疏长环、多类标签与重复相关权重的等价训练。若最近邻已有等价方法和同监督，无需进入模型实现。 [技术矩阵](02_Literature_and_Transfer_Matrix.md)

## Stage 1｜低成本假设验证（通过数据门后）

| 要素 | 预注册设计 |
|---|---|
| 数据与任务 | 选择一个达到门槛的实际标签数据域，开发和评估组不可重叠；有 S/B/U 时加 VLSU-GroupSplit 三分类两条基线。二类有环时仅做机制桥接，若引入 VLSU 充作辅助域，使用独立域头与等额标签对照 |
| 训练 | 同一缓存 OpenCLIP ViT-B/32 或 ViT-B/16，统一图像分辨率和文本裁剪。CE 联合、CE+单模态多任务、同架构+环目标三条等步数，加入 Cycle OE 和逐边 CE/配对排序。Cycle OE 保留作者二类完整棋盘基线，另做多类同信息适配。用 3 个事前种子，少量固定 \(\lambda\) 网格仅在开发。三路都可见同一训练数据。无真实单侧等级的域去掉 MTL，对比保持其他可得监督一致，三路试验仍在独立 VLSU-GroupSplit 上报告 |
| 参照 | 无学习的组先验、max 标签、同头的严格加性输入预测（全部为预测联合标签，另做单侧任务诊断），同输入 MLP，固定等权四格差分。Cycle OE 同信息适配，二元棋盘用原始 softplus(−Δ)；其它非零多类对比以固定图和标签向量作方向归一化的 softplus 边际。若标准矩形少，另报支持覆盖，避免比较完全不同的评测子集。先跑小矩阵单位检查，再做缓存 |
| 首要机制指标 | 预注册非零目标对比的方向准确率或对应归一化环损误差。多环按 \(\langle P_WZ,P_WT\rangle_W\) 的符号判方向，与环基选择无关；归一化误差除以 \(\|P_WT\|^2_W\)，同时报告反向、平局和正确率。对独立二类完整矩形另报原版 CycleAcc，平局按 0.5，并与多类四格全对分开。主实现不可依赖评估时重新估模型参数。独立簇用于配对比较 |
| 分类与保持指标 | Acc、Macro-F1、每类 P/R/F1、混淆矩阵、Brier/NLL、U→S/U→B 及 S→U。报告非关键变化上的决策一致性与概率稳定性。正负对照分别检查配对方向是否正确和无关因素不应改变结果 |
| 资源估算 | ViT-B 冻结全局向量，batch 16–64，分辨率 224 或所选权重原生，缓存可低于约 5–8 GiB GPU，头训练需求更低，实际依赖 CUDA 与骨干。2 个 512 维 fp16 向量每 8,159 个样本约 16 MiB。先跑 100 样本给出解码、编码吞吐与峰值，以实测外推。初筛每域缓存 0.5–2 GPU 小时，头训练每种子约 5–30 分钟；若 I/O 慢批量预先缓存，单次任务设 6 小时上限，禁止假定实际可达 |
| 继续条件 | 与最强同预算基线相比，独立组上的方向准确率提升预设最小实用差（小试建议 +5 个百分点）或可对齐的主对比误差改善，组 bootstrap 配对区间有支持、3 种子方向一致；整体 Macro-F1 与 U→S 指标相对验证门槛无明显恶化（小试容许 1 和 2 个百分点），且错线与同标签保持对照符合预期。建议量级仅用于投资判断，正式差值用设计时的功效分析冻结 |
| 停止条件 | 图零支持、同数据 CE/排序能复现改善、只在错误标图或单一数据源出现、方向或误报明显恶化、实际资源突破上限。区间宽、无法判定的结果列证据不足；有已授权独立数据时一次扩样确认，无信号则转 B 或结束 |

**怎样读 B-B-U 和 S-S-U。** 逐组给正确例数、原/可用样本数、Wilson 或聚类区间，不能把少数 AUROC 样本认成完整分组估计。单固定真实 yJ 的组，正确率就是该目标类的条件召回，计算该组 Macro-F1 会误导。提供混淆的流向和多组指标。比较两个模型时用共同图像清单、配对组 bootstrap 10,000 次（测试组与种子分层报告），种子 5 个进入正式实验。小样本二元配对用 exact McNemar 或组置换作辅助，多组探索按 Holm/FDR 校正或标探索，不靠最高的点估计选择机制。

## Stage 2｜方法实现与公平对照

固定骨干和训练数据，代码优先复用 [OpenCLIP](https://github.com/mlfoundations/open_clip) 特征接口和 [Hate-CLIPper](https://github.com/gokulkarthik/hateclipper) 的图文分类流程，构图用 scipy 稀疏矩阵或小块 NumPy。低秩交互与加性头可在同实现切换。中后期再用可重复的局部 token cross-attention 与第二个骨干，单卡 16–20 GiB，记录 batch、精度、峰值 allocated/reserved、可训练参数、缓存与优化步数。小头可复用为人可审计的无服务脚本。这个计划不以大规模训练、付费 API 或 8B 全量 DPO 为依赖。

| 比较 | 其余变量锁定 | 归因 |
|---|---|---|
| CLIP+MLP、Hate-CLIPper、cross-attention、严格加性、MRO、UMR、检索对比、MTL、CSSC | 同 encoder/预处理/训练样本数，参数/算力匹配 shortlist | 排除骨干、容量、辅助和架构选择 |
| 无单模态头、有同标签头、有置换单模态标签头 | 相同联合头、预训练和更新 | 分辨三重真值贡献与多头正则 |
| 同头 \(\lambda=0\) vs 真环、Cycle OE、同配对排序、同图同 label 平滑、同标签非配对监督、错线 | 等配对数据、采样与优化步 | 分离学习目标、信息与标签平滑 |
| 简单均匀权、同策略配对、族留出、长环/矩形、协方差校正 | 固定分类训练、输入和步骤 | 图的覆盖与环重复权重；等价实现应一致 |
| 固定重加权开关、matched-width、matched-steps、same-data extra-epoch | 一次只改一个量 | 发现收益是否来自采样、参数、读取数或额外预算 |

开放 VLM 至少一个强通用模型（如 Qwen2.5-VL-7B 或可合法获取的同级更新权重）与代表专用模型。直接标签 prompt 与预算匹配的 Structured-CoT 用同一个测试子集、共同文本/分辨率上限、解析法和安全规范；每个解析失败单列并明确主分母。可用 ThinkingGuard、HoliSafe guard 做各自二元评测或标为三类适配，ExPO-HM 和 RA-HMD 在同二类目标上保留为强对照，FBHM 的 LSV、MemePIVOT、TIDC 作为有共享实验/匹配数据时的直接机制比较。官方 GPT/Gemini 数据只放原协议参考列，无需新增付费调用。所有近邻本来领用的外部数据、训练量与检索条件清楚报告。 [VLSU 正式结果](https://proceedings.iclr.cc/paper_files/paper/2026/file/a36e092659c42b2c92b8b0eb2394bf74-Paper-Conference.pdf) · [强方法来源](02_Literature_and_Transfer_Matrix.md)

## Stage 3｜完整机制、性能与迁移

### 机制验证

1. 对同一 I,T 分别跑 image-only、text-only、joint。前两项报告各自标签准确率；另训练只见 I/T 但要预测 **联合** 标签的两个探针，以测联合作答能被哪侧预测。比较加性模型、OCR-only、精简图/原图、去文本重复、mask 随机种子、输入长度和域来源探针。
2. 对真实配对用相同全文变图、相同图变文、两者完整复用的对照阶梯。优先作者批准的关键视觉/文字干预，独立核验语义与政策；位置、面积、物体置信和文本编辑长度匹配非关键对照。对无金标的灰图遮盖、随机错接、裁剪和扰动只记录模型敏感性，不用原 yJ 当反事实金标。
3. 同等级异 yJ 进行条件比较，按题材和模板配对，以盲确定的真实改变算方向，固定 B↔S、U↔B、U↔S 的数量和可见证据。仪表报告 P(两单侧正确 | 联合错) 和 P(联合错 | 两单侧正确)；加“两个侧标签都可得、分母中何时缺图”的覆盖。对可信 S-B-U、U-S-B 等例检查是视觉事实、文字理解、关系还是政策决策。少量 label-preserving 图文例中可用固定事实作为诊断输入，单列额外信息预算。
4. 预测整幅图扰动不证明哪个 token 是因果证据。只有受控反事实且带可靠标签、跨组独立保持效果、对替代解释有预注册负对照时，才可以写模型行为依赖关系证据。对更强的内部机制另需 activation/representational intervention 及对照，本论文不依赖它。

### 迁移与公开数据盘点

| 目标与推荐用途 | 标签、来源及注意 |
|---|---|
| **Hateful Memes**，首选目标 | Hateful / Non-hateful，NeurIPS 2020，benign confounders 适合成对诊断。官方 Phase 2 取得协议，使用释放的 train、dev、带标签 official test_seen/test_unseen 套件；若当前 official test 标签不可取得只能作盲测提交或论文明示其他公开 split。保留官方 AUROC/Acc，同时报告 Macro-F1 与各类指标。 [论文](https://proceedings.neurips.cc/paper_files/paper/2020/hash/1b84c4cee2b8b3d823b30e2d604b1878-Abstract.html) · [条款](https://www.drivendata.org/competitions/70/hateful-memesphase/) |
| **Harm-C / Harm-P（HarMeme）**，第二目标 | 标签是 harmfulness。原始部分数据有程度标签，按公开设定合并 very/somewhat harmful→harmful 时明确映射、保留官方分割。Harm-C 与 Harm-P 不可随意混合 test。核可后用 [原任务论文](https://aclanthology.org/2021.findings-acl.246/) 及 [RA-HMD 使用协议](https://aclanthology.org/2025.emnlp-main.1215/) |
| **MAMI Task A**，备选目标 | Misogynous / Non-misogynous，SemEval 2022，使用竞赛标注与官方训练/测试；Task B 多标签另列。性别主题窄，不能视作 VLSU Unsafe。 [原任务论文](https://aclanthology.org/2022.semeval-1.74/) |
| **HoliSafe 或 MSSBench**，独立输入安全二类 | Safe / Unsafe；受控策略和可用图需核查，二者任务及标签创建机制不同。独立测试上不学习阈值，MSSBench 使用经确认的配对子集和正确任务定义。 [HoliSafe](https://youngwanlee.github.io/holisafe/) · [MSSBench](https://github.com/UCSB-AI/MSSBench) |
| **Offensive / Non-offensive** | 如 MultiOFF 仅在取得原数据与授权、确认官方划分后可加，作为通用攻击性下游，保留其自身规范与指标，不并入 hate 和 input safety。 |

**核心 4 路从同 backbone 初始化。** A 直接训练目标头。B 源域 VLSU 三分类 CE，然后重置目标任务头。C 相同源数据，三重标签辅助。D 同源同预算加入已验证交互目标。D 如需使用额外配对数据，增加 B+/C+，与 D 看到完全相同的附加边、数据量、步骤与分类标签，只变环损失。若源图仅二类有环，预训练使用独立二类辅助头，保留严格配对数据的常规 CE 额外对照，并将真正的三类闭环证据列为待达。B/C/D 必须只看 VLSU 源 train，测试集按上面的协议独立。A 的源训练为零是干预变量，共同控制目标步数，另加同计算无标签源预训练对照区分训练开销。禁止使用 HM 目标 test 参与任何源训练或采样。

- Frozen encoder + linear probe 应从训练过的图文投影或交互表征读取。只探冻结而完全相同的初始 backbone 时 A–D 按定义应相同，这可作完整性对照。目标阶段统一输入、头、种子和调参预算。
- 1%、5%、10%、100% 只抽官方目标 train。分层嵌套抽样，每个比例在不同种子使用可追溯样本 ID，与类别极少时最低数规则一并公布。保持验证集一致和目标测试全量，给学习曲线及置信区间。额外测试无目标训练的 zero-shot/policy transfer 时，固定二类标签映射和温度；找不到合理映射则按各数据语义单独报告。
- 源—目标跨域按底图像素、近重复、OCR、prompt、模板、来源分组。MemeCF 可能含来自 HM/HarMeme 的原例，目标域作为测试时优先从源域删除同源组。RA-HMD 式目标检索只用目标 train，等规模、相同候选库与标签预算。迁移性能增益是预测证据，关系理解证据由独立对照承担。
- 耗时与显存每次记录实际设备、版本、batch、混合精度和 checkpoint。token 版若不能在显存预算内做公平训练，保留小头对照并记录实际可达上限。主指标不依赖集群资源。台账保留随机种子、参数量、单条 p50/p95、总样本吞吐和缓存构图预处理耗时。

## Stage 4｜撰写与决策

| 阶段与成本 | 过门条件 | 失败处置 |
|---|---|---|
| Stage 0，1–3 人日、CPU | 授权、数据版本、同策略真实标签、训练/测试支持、近邻比较可查 | 无满足的闭环时转 B；VLSU 仍可做常规研究诊断 |
| Stage 1，按次 ≤6 h，3 种子 | 同数据对照上存在预设差，验证不会被泄漏、采样、分母解释 | 否决当前机制或只验证一个未判定环节，避免增加工程 |
| Stage 2，约 3–7 工作日，以实测为准 | 对照和失败记录齐全，第二骨干或独立族复验 | 保留最小方法，失败则回退到数据/问题审计 |
| Stage 3，按共享资源约 2–4 周 | 主、机制、迁移、效率各有独立结论，两个相关来源或显式边界 | 迁移阴性如实保留，若分类只在一来源成立则收窄结论 |
| Stage 4，约 1–2 周 | 主要主张有对应证据和区间，基准协议、版权和代码可复现 | 可转数据测量报告或重新选题，不用大模型或新增数据抬出正结果 |

实际时间会受到图像版权、下载、机器可用率和共享 GPU 调度影响。资源投入顺序以[决策摘要](00_Executive_Decision_Memo.md)与本页门槛为准。
