# Stage 1 image acquisition design

**LOCAL REPRODUCTION design.** Stage 0 uses synthetic bytes and synthetic DNS results to exercise the CPU checks. Live network handling and release-wide coverage are **NOT RUN**. Start Stage 1 with implementation and synthetic HTTP integration tests, followed by a bounded real smoke test and then the complete CPU coverage run. Use the pinned CSV unchanged and recheck its Git blob and byte SHA-256.

1. Import every UUID, original URL and pattern into an ignored SQLite manifest keyed by CSV SHA-256 and UUID. Queue exact URL strings once per run and fan each outcome out to all corresponding UUIDs. Keep URL, redirect history, final URL, response status, timestamps, validators, attempts, download state and decode state. Publish only aggregate counts. Store the DB, partials, images and local logs within `.local/`.
2. Use a fixed worker budget of 8, concurrency 1 and at most 1 request per second per destination host, including redirects. Apply both host and global limits. Suggested local defaults are 5 s connect, 10 s read idle and 30 s per request, at most 3 attempts and 5 redirect hops. Retry transient DNS/connect/read timeouts, 408, 429 and transient 5xx with exponential backoff and jitter. Respect integer and HTTP-date Retry-After, including host-wide deferral. Persist deferred timestamps and retry reasons. Treat 401/403/404/410, disallowed destinations, and legal or access restrictions as terminal. Preserve the original failed outcome.
3. Permit HTTP/HTTPS on default service ports, with no credentials. Resolve A/AAAA and reject non-public results, including private, loopback, link-local, local IPv6 and IPv4-mapped non-public addresses. Revalidate each redirect and each fresh resolution. Connect only to a vetted address for that attempt, keep the original hostname for Host and TLS SNI/certificate verification, verify the connected peer and disable inherited proxies and automatic redirects. Treat resolver/connector errors as explicit failures. Do not carry cookies or authorization across requests. The CPU target helper validates the supplied answers. DNS pinning, peer verification and redirect control belong to the Stage 1 transport layer.
4. Stream with a hard 20 MiB transport and persisted-object cap and request identity encoding. Check declared size and cumulative bytes, including resumed bytes. Write per-URL temporary files. Resume a partial only with matching strong ETag, identity encoding, Range and If-Range, plus a validated 206 Content-Range and consistent total length. Otherwise discard the partial and start a fresh attempt. Handle 416 by revalidating the object or restarting within limits. Record partial bytes and validator transactionally. On cancellation, checkpoint. Resume completed verified entries by digest and expired in-flight leases by retry. Use atomic publication of validated objects and a DB transaction to link each UUID.
5. Record HTTP/body acceptance separately from content validation. Enforce an image Content-Type that agrees with Pillow's detected MIME. Verify, reopen and load with a 25 MP limit and decompression bomb errors. Run the decoder in a restricted worker with memory and wall-clock limits. Record format, dimensions and animation; Stage 1 coverage measures first-frame decode. Animated sample representation for model input remains a separate recorded preprocessing decision. Preserve original bytes and SHA-256. Deduplicate by content hash after validation. On re-fetch, retain the old and new hashes with date, validators and outcome when bytes change. Historical identity to the authors' cached images is UNKNOWN. A substituted mirror, archive copy or replacement image would require separate provenance and a separate result.
6. Emit an immutable availability roster and summaries by UUID, unique URL, gold label and pattern, including extra and uncertain groups. Report accepted download, verified decode, download failure and decode failure with counts and denominators. Keep all release queries eligible for text-only evaluation. For image-requiring tasks preserve missing-image UUIDs and coverage. Stage 2 is gated on the Stage 1 coverage audit and an explicit review of failure concentration.

The Apple helper downloads into per-UUID files, verifies via Pillow and converts WebP to PNG, with a file-signature fallback and a generic manual retry marker. It does not establish this design's transport guarantees, actual release coverage or author cache identity.
