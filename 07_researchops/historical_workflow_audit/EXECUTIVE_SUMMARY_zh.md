# 历史工作流：直接回答

1. **主要怎么运行？** 已核查案例中，Codex 经自己的命令工具启动前台长命令并轮询；也有 Shell 内 & + wait 的并行 worker，另见一次 nohup。当前科研 tmux session 承载 Codex CLI 本身，不能据此算成 tmux 启动的实验。[E013,E015,E016,E017,E018]
2. **各方式多少次？** 截至 2026-11-25 的 81 个会话中，找到 9 条含 Shell 后台 & 的启动命令、1 条 nohup；未找到 Codex 调用 tmux 启动实验、screen 启动实验或 Slurm 提交命令。前台方式存在大量调用，尚未逐条去重成实验数；本报告的 9 个代表任务组中前台 3 组、Shell 并行后台且等待 5 组、nohup 1 组。它们是样本下限，不能外推为全部历史实验。[E012,E018]
3. **怎样判断结束？** TRACE 和 ASIMOV 可看到统一命令会话的退出码 0；MSSBench 还查日志、SQLite 终态数和导出，但外层 cell 的最终退出码未找到。退出 0 不等于每条预测都完整，完整也不等于指标已独立复算。[E015,E016,E017,E020,E023]
4. **关掉 Codex/SSH 后能否继续？** tmux 可以保留其中的 Codex CLI；nohup 独立进程可在终端断开后继续；普通统一命令会话和 & + wait 是否在 CLI/SSH 退出后继续，历史证据不足，不能承诺。未找到每次重连后的自动恢复监控机制。[E013,E016,E018]
5. **代码在哪里？** 多个 Git 工作目录和仓库外目录；TRACE 两份仓库副本，H1、VLSU 的部分脚本与运行产物在仓库外。[E019]
6. **上传什么？** PR #80 上传报告、复算脚本和 820 行评分；#81 上传代码、配置、指标、两个各 254 行逐例评分；#79 上传结果、traces 和大量日志；TRACE 分支上传代码、事件与汇总，但私有 Caption/权重/Checkpoint 未上传。[E020,E022,E023,E026]
7. **原始指标与日志？** 不统一。#80 有分数无 worker 日志；#81 有逐例评分无独立过程日志；#79 两者兼有；TRACE 有每步事件、私有 Checkpoint，缺公开样本级预测。[E020,E022,E023,E026]
