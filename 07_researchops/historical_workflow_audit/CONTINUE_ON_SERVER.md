# 在可连通实验室内网的 Codex CLI 中继续只读审计

本文件是 PR #82 的接续任务入口。当前 PR 仅包含 GitHub 侧阶段性审计，不能作为完整结论。

请在用户**已验证能连接跳板机和实验服务器的本机 Codex CLI 环境**执行。服务器地址和认证方式由用户本机已有 SSH 配置或交互登录提供；**不要将密码写入命令、文件、GitHub 或会话摘要**。

## 工作范围

1. 读取 PR #82 及 `07_researchops/historical_workflow_audit/` 中已有报告、矩阵与证据 ID，保留现有 GitHub 侧证据和边界。
2. 从本机经两跳 SSH 进入实验服务器。先验证实际 hostname、whoami、工作目录与 Codex CLI 版本；确认进入的是用户本人科研环境。不要修改 SSH 配置，也不要绕过主机密钥警告。
3. 只读盘点本人项目目录、相关 Git 仓库、`~/.codex` 会话结构、Shell history、本人进程、tmux/screen/Slurm 状态、运行日志、journal 和结果文件。避免扫描共享服务器其他用户目录。不要读取、复制或提交私钥、Token、密码、完整私密会话、原始图文和模型权重。
4. 对至少 ASIMOV、EMBGuard、MSSBench Stage 1/2、VLSU/Kill Test 中能找到的实验建立任务文档→取仓库→代码落盘→启动命令→进程托管→完成判断→产物→Git 提交的证据链。逐项区分实际工具调用、脚本内容、日志和报告自述。
5. 分别统计 Linux 进程管理方式（前台、nohup/后台、tmux、screen、Slurm）和 Codex 工具持久会话，记录统计范围和未知项。脚本同步调用 Python 与外层后台托管可能重叠，不重复计数。
6. 对比服务器本地与 GitHub PR/分支/main 的代码、配置、原始指标、样本级分数、日志、失败记录与精确版本。检查运行代码是否可对应提交 SHA，是否有未跟踪或未上传产物。仅提取脱敏摘要和必要的证据定位。
7. 更新 PR #82 的中文报告、四张 CSV、流程图与 evidence registry；新增 SERVER_SIDE_AUDIT_zh.md 记录只读命令、取证范围、访问限制与核验日期。已有“未知”只有在证据足够时才改成确定值。
8. 不启动 GPU，不安装软件，不更改服务器配置，不停止/干扰实验，不合并 PR。将脱敏结果提交到 PR #82 原分支，保留 Draft。报告最终直接回答用户的两个重点：历次运行方式和每次上传了哪些内容。

如果无法读取某类历史会话，标记该类统计的覆盖率和原因。不要把未找到等同于从未发生。
