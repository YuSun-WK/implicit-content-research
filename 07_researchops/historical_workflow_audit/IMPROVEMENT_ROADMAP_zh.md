1. **P0：补完服务器侧调查。** 先核实 Codex 会话、shell 历史、本地 Git 状态、实验 PID/journal/log；这决定是否需要 tmux、调度器或 runner。只读进行，不打断实验。
2. **P0：建立跨分支实验索引。** 每个实验记录 PR/commit、状态（开放/关闭/合并）、结果入口。当前 #80/#81 未合并是具体检索盲点；可用一页索引，成本低，不影响训练。
3. **P1：启动时固定 run manifest。** 记录 task ID、准确 commit、工作区是否干净、完整命令、数据/模型 revision、GPU UUID、日志路径、随机种子。解决 #79 日志可见但外层启动与代码状态无法追溯的问题；在下一次实验试用，避免改动正在运行的任务。
4. **P1：结束状态单独落盘。** 保存 PID/Job ID、退出码、时间、预期/实际样本数与结果校验。当前 #79 的 SQLite 检查可复用，不必新建平台。
5. **P1：明确每种实验的轻量归档清单。** 包含代码、配置、运行命令、版本、日志、程序原始输出、复算器与失败记录；对受许可或体积限制的数据只留哈希和合法的脱敏导出。参考 #79 与 #81 的已有做法。

只有在服务器证实当前机制不足时，才决定引入 worktree、tmux/Slurm、非交互 Codex 或自动任务领取。
